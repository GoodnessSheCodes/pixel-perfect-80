# MediVault AI — Build Plan

Full working prototype per the uploaded brief, built in stages on Lovable Cloud (auth, database, server logic) with the Lovable AI Gateway for the assistant.

## Stage 1 — Foundation
- Enable Lovable Cloud; email/password sign-in.
- Design system: white surfaces, teal primary, deep blue, restrained green; calm clinical typography (e.g. Manrope + Source Serif accents avoided → Manrope/IBM Plex Sans).
- Public landing page with demo-data + POPIA notice, sign-in/register (choose Patient or Doctor).

## Stage 2 — Data model & security
Tables: profiles, user_roles (patient/doctor/admin, separate table), patients (unique ID like `MV-XXXX-XXXX`), doctor_profiles (HPCSA no., verification status), consultations, prescriptions + prescription_items, access_grants (consent), notifications, audit_logs.
- Row-level security everywhere: patients see only own data; doctors only patients with an active grant; admins via role check.
- Patient ID generated by trigger on signup. Prescriptions immutable once issued (no update/delete policies for patients; corrections via doctor amendment record).
- Sensitive actions (search, grant request, issue prescription) run as server functions that write audit logs; search returns only name initials, birth year, and ID to prevent enumeration.

## Stage 3 — Patient app
Dashboard (ID, counts, recent prescriptions, follow-ups, allergies, activity), Medical History timeline + detail, Prescriptions (status, view/print/download), Notifications, Profile & Privacy (edit permitted fields, approve/revoke doctor access, access history).

## Stage 4 — Doctor app
Dashboard, patient search by ID/username, identity verification step (confirm DOB + name), access request → patient approves (or patient-provided one-time access code for in-person visits), authorised record view, consultation form, prescription builder with review/confirm dialog, issued list with delivered/viewed status. Unverified doctors blocked server-side from clinical writes.

## Stage 5 — AI assistant
Patient chat that receives only that patient's records, strict system prompt (no diagnosis/dosage changes, flag missing info, emergency redirect), responses labelled "AI-generated explanation" + disclaimer. Quick actions: explain terms, summarise history, summarise prescription, prepare questions.

## Stage 6 — Admin & demo
Admin page: approve/reject doctors, audit log viewer, reset demo data. Seeded fictional accounts: Thandi Molefe (allergy + 2 consultations), verified Dr demo, unverified doctor, admin — credentials shown on the landing page.

## Stage 7 — Test
Run the full Thandi scenario end-to-end in the browser, plus checks that other patients' records and unverified-doctor prescribing are blocked.

## Technical notes
TanStack Start routes under `_authenticated/` split into `/patient/*`, `/doctor/*`, `/admin/*` with role gates; createServerFn + requireSupabaseAuth for sensitive ops; AI via server function calling Lovable AI Gateway (google/gemini-3-flash-preview).
